# Accessibility & Usability Review - Lab 04

การตรวจสอบความเข้าถึงได้ (Accessibility) และความง่ายในการใช้งาน (Usability) ของ UI Mockup ตามมาตรฐาน WCAG 2.1 ระดับ AA

## 1. ตารางแบบตรวจ Accessibility Checklist

| รายการตรวจ | ผ่าน หรือ ไม่ผ่าน | สิ่งที่แก้ / คำอธิบายเพิ่มเติม |
|---|:---:|---|
| **ข้อความหลักบนพื้นขาว contrast อย่างน้อย 4.5 ต่อ 1** | **ผ่าน** | ใช้สีข้อความหลัก `#111827` บนพื้นหลังสีขาว `#FFFFFF` ซึ่งมี Contrast Ratio สูงถึง **15.8:1** (ผ่านเกณฑ์ระดับ AAA เกินเกณฑ์ 4.5:1) |
| **ปุ่มหลัก (Primary Button) มี contrast เพียงพอ** | **ผ่าน** | ใช้ปุ่มพื้นหลังสี `#1E40AF` พร้อมตัวอักษรสีขาว `#FFFFFF` มี Contrast Ratio เท่ากับ **8.5:1** (ผ่านเกณฑ์ AA และ AAA) |
| **ทุกช่องกรอกมี label ที่มองเห็น** | **ผ่าน** | มีการแสดง `<label>` ข้อความกำกับอยู่ด้านบนของทุกช่อง Input ตลอดเวลา ไม่ได้พึ่งพาเพียง Placeholder ที่จะหายไปเมื่อพิมพ์ |
| **ช่องที่บังคับกรอกมีสัญลักษณ์ชัด** | **ผ่าน** | กำกับด้วยเครื่องหมายดอกจันสีแดงและข้อความชัดเจน เช่น `*` (Required) พร้อมระบุว่าช่องใดบังคับกรอก |
| **error ไม่ได้ใช้สีอย่างเดียว มีไอคอนหรือข้อความด้วย** | **ผ่าน** | เมื่อเกิด Validation Error จะมีไอคอนเตือน `⚠️` หรือ `[!]` ประกอบกับข้อความอธิบายวิธีแก้ไข ไม่ได้เปลี่ยนเพียงสีกรอบสีแดงอย่างเดียว |
| **ลำดับการกด Tab เรียงบนลงล่าง ซ้ายไปขวา** | **ผ่าน** | วางโครงสร้าง DOM และลำดับ TabIndex ตาม Flow การทำงาน จากบนลงล่างและซ้ายไปขวา ช่วยให้พนักงานคลังสินค้ากรอกข้อมูลผ่านแป้นพิมพ์ได้ต่อเนื่อง |
| **ปุ่มมีชื่อบอกหน้าที่ ไม่ใช่ OK หรือกากบาท** | **ผ่าน** | ตั้งชื่อปุ่มตามฟังก์ชันจริง เช่น `"บันทึกสินค้าใหม่"`, `"ยกเลิก"`, `"เข้าสู่ระบบ"` ทำให้ผู้ใช้เข้าใจผลลัพธ์ที่จะเกิดขึ้นก่อนคลิก |

## 2. จุดที่ AI ทำพลาดและนักศึกษาแก้ไขด้วยตนเอง (อย่างน้อย 2 จุด)

จากการสั่งให้ AI ร่างแบบฟอร์มและหน้าจอ UI ในรอบแรก พบข้อผิดพลาดด้าน Accessibility 3 จุด และได้ทำการแก้ไขปรับปรุงดังนี้:

### จุดที่ 1: AI ใช้ Placeholder แทน Label ถาวรในช่องกรอกข้อมูล
* **สิ่งที่ AI ทำมา (บกพร่อง):**
  AI สร้างโค้ดหน้า Add Product โดยไม่มีแท็ก `<label>` ด้านบน แต่ใส่ข้อความเป็น `placeholder="กรอกชื่อสินค้า..."` ไว้ในช่อง input โดยตรง
* **ผลกระทบด้าน Accessibility / Usability:**
  เมื่อผู้ใช้เริ่มพิมพ์ข้อความ Placeholder จะเลือนหายไป ทำให้ผู้ใช้ที่มีสมาธิสั้นหรือพนักงานที่ต้องมองสลับระหว่างเอกสารกระดาษกับหน้าจอจำไม่ได้ว่าช่องนี้คือข้อมูลอะไร นอกจากนี้ Screen Reader สำหรับผู้พิการทางสายตาอาจอ่านข้ามช่องกรอกที่ไม่มี Label
* **การแก้ไข:**
  เพิ่ม `<label>` ถาวรไว้ด้านบนเหนือช่อง Input ทุกช่อง และคงข้อความตัวอย่างสั้นๆ ไว้ใน Placeholder เพื่อเป็นตัวอย่างฟอร์แมตข้อมูลเท่านั้น

---

### จุดที่ 2: ข้อความแจ้งเตือน Error แสดงผลคลุมเครือและใช้สีเทาอ่อน Contrast ไม่ผ่าน
* **สิ่งที่ AI ทำมา (บกพร่อง):**
  เมื่อผู้ใช้กรอกราคาเป็นค่าติดลบ AI แสดงข้อความ Error สั้นๆ ใต้ช่องกรอกว่า `"Invalid input"` โดยใช้สีตัวอักษรสีเทา `#9CA3AF` บนพื้นขาว ซึ่งมี Contrast Ratio เพียง `2.5:1` (ต่ำกว่าเกณฑ์มาตรฐาน 4.5:1)
* **ผลกระทบด้าน Accessibility / Usability:**
  ผู้ใช้ที่สายตาเลือนรางมองเห็นข้อความเตือนได้ยาก และผู้ใช้ไม่เข้าใจว่าตนเองทำผิดตรงไหน ต้องแก้อย่างไร
* **การแก้ไข:**
  เปลี่ยนสีข้อความแจ้งเตือนเป็นสีข้อความเข้ม `#B45309` (Contrast 4.8:1) พร้อมใส่ไอคอน `⚠️` และเปลี่ยนข้อความแจ้งเตือนเป็นประโยคชี้แนะที่ชัดเจน เช่น `"ราคาต้องเป็นตัวเลขที่มากกว่า 0 บาท"`

---

### จุดที่ 3: ปุ่มดำเนินการหลักและปุ่มยกเลิกใช้คำกำกับคลุมเครือ ("OK" และ "Cancel")
* **สิ่งที่ AI ทำมา (บกพร่อง):**
  AI สร้างปุ่มบันทึกและปุ่มยกเลิกโดยใช้ข้อความบนปุ่มว่า `"OK"` และ `"Cancel"` วางติดกันโดยใช้สไตล์คล้ายคลึงกัน
* **ผลกระทบด้าน Accessibility / Usability:**
  คำว่า "OK" ไม่ได้สื่อสารว่าการกดปุ่มจะทำการบันทึกข้อมูลเข้าสู่ฐานข้อมูลคลังสินค้า ทำให้ผู้ใช้เกิดความลังเล และมีความเสี่ยงสูงที่จะกดปุ่มผิด
* **การแก้ไข:**
  เปลี่ยนชื่อปุ่มเป็นกริยาที่ชัดเจนคือ `"บันทึกสินค้าใหม่"` (ปุ่มสีน้ำเงิน Primary `#1E40AF`) และแยกปุ่ม `"ยกเลิก"` (สีเทารอง Secondary) ออกจากกันอย่างชัดเจน
